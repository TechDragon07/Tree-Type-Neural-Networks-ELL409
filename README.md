# Corrective Neural Trees for Image Classification

This is the complete implementation and experimental record for an ELL409
study of tree-type neural networks on CIFAR-10 and Cats vs Dogs. The work asks
whether a sequence of small, interpretable neural corrections can deliberately
interpolate a finite training sample, what fails as residual groups become
small, whether a reproducible double-descent pattern appears near
interpolation, and how much of the grown structure can subsequently be removed.

The formal submission is
[`report/corrective_neural_tree_report.pdf`](report/corrective_neural_tree_report.pdf).
Its LaTeX source, measured artifacts, and all implementation details are kept in
this private repository.

## Research contribution

The model is not a conventional CNN with a tree-shaped diagram added after the
fact. It operationalizes the class formulation:

\[
L_K(x)=L_0(x)+\sum_{k=1}^{K}a_k(x)(e_{t_k}-e_{p_k}),\qquad a_k(x)\ge0.
\]

`L0` is a neural root. Every `a_k` is produced by a separate two-layer neural
network. The fixed direction raises a class the current model missed and lowers
the class it predicted incorrectly. This gives an exact multiclass version of
positive false-negative and negative false-positive branches.

The central implementation choices are:

- a compact shared convolutional trunk;
- GroupNorm in the trunk and LayerNorm in heads, avoiding small-batch
  BatchNorm failure;
- deliberate early stopping of the root below interpolation;
- greedy spawning from the dominant ordered confusion;
- frozen old nodes and cached embeddings during child training;
- learned inference gates, so routing never uses ground-truth labels;
- near-zero child initialization and rejection of non-improving expansions;
- repeated-seed, measured-parameter capacity sweeps;
- input-gradient effective receptive fields;
- leave-one-node-out greedy pruning.

The design, objective, invariants, and regression extension are derived in
[`docs/architecture.md`](docs/architecture.md).

## Principal measured findings

All numbers below are controlled-subset measurements generated by committed
JSON artifacts, not full-dataset benchmarks.

- **CIFAR-10 interpolation:** on 256 training images, the root reached 91.02%
  train / 29.50% test. Eleven corrective nodes reached 100.00% train / 29.80%
  test. Training fit improved by 8.98 points, but test cross-entropy worsened
  from 2.041 to 2.148.
- **Cats-vs-Dogs interpolation:** on 256 training and 256 test images, the root
  reached 91.41% train / 68.75% test. Two opposite-direction children reached
  100.00% train while test accuracy fell to 63.67%; test cross-entropy rose
  from 0.645 to 1.315.
- **Minimization:** relaxing the CIFAR training floor to 99% removed the final
  two nodes, reduced parameters by 6.9%, and retained 99.22% train / 29.70%
  test. Neither binary child could be removed.
- **Controlled double descent:** a 64-example CIFAR-10 sweep with 10% training
  label noise met the predeclared criterion in two of three seeds. Mean test
  accuracy fell to 8.07% before interpolation, then increased from 11.33% at
  the first universally interpolating width to 22.14% at width 64.
- **Negative replication:** Cats vs Dogs supported the criterion in only one
  of three seeds. Its largest models also left interpolation under the fixed
  optimization budget, so its curve cannot be called post-interpolation double
  descent.
- **Routing failure revealed by ERFs:** the CIFAR bird<-frog child activates
  most strongly on an actual frog, and the binary dog->cat child reaches gate
  1.000 on an actual dog. Sign-constrained directions remain harmful when the
  learned gate identifies source-class evidence instead of missed-target
  membership.

The important conclusion is not simply that both trees can memorize. The
experiments isolate *how* they memorize: route networks overfit residual
membership, confidence degrades before accuracy visibly changes, and the
marginal nodes needed for exact interpolation can be disproportionately
expensive.

## What “tree” means here

This is a **stage-wise additive corrective tree**. Its hierarchy is the
ancestry of residual problems: node \(k\) is trained on the errors left by
nodes \(0,\ldots,k-1\). All retained corrections are evaluated at inference.
It is not a hard decision tree that executes exactly one branch. This is
consistent with the additive parent/child score in the motivating formulation,
but it means depth is not identical to inference latency. The distinction is
reported explicitly instead of hiding it behind tree terminology.

## Datasets

### CIFAR-10

The project uses the official 50,000/10,000 train/test data. The images can be
downloaded through torchvision or the Hugging Face mirror; source choice is
stored in the run configuration. Ten-way correction nodes are attached to
ordered confusion pairs such as `cat <- dog`.

### Cats vs Dogs

The binary task uses Oxford-IIIT Pet and its official `binary-category` target.
This avoids manually inferring species from breed names and provides official
`trainval` and `test` splits. It is a reproducible replacement for
credential-dependent Kaggle packaging of the same task.

## Optimization in brief

The root and trunk first minimize cross-entropy. Root training stops at a
separate `root_target_accuracy`, intentionally leaving errors for tree growth.
The trunk and root are then frozen.

For proposed pair \((t,p)\), a child produces

\[
m_k=\operatorname{softplus}(u_k),\quad
g_k=\operatorname{sigmoid}(v_k),\quad
a_k=m_kg_k.
\]

The child objective combines:

1. inverse-frequency-weighted corrected cross-entropy;
2. weighted binary cross-entropy for the learned route;
3. a gate sparsity penalty.

The child is retained only if some epoch improves complete cached-training
accuracy. Full derivations and the reason for each term are in the architecture
document.

## Experimental claims policy

Interpolation means at least 99.9% training accuracy. A non-monotone test curve
is not automatically called double descent. The automated criterion requires
at least three independent seeds, a rise near each seed's first interpolating
capacity, a later fall, and agreement from at least two-thirds of seeds.

The repository separates a bounded controlled CPU study from full-dataset GPU
runs. Controlled-subset results are useful for mechanism discovery but are
never relabeled as full-dataset performance.

The complete protocol, hypotheses, interpretation rules, and validity threats
are in
[`docs/experimental_protocol.md`](docs/experimental_protocol.md).

## Installation

Python 3.10 or newer is required.

```powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check .
```

For CUDA, install the appropriate PyTorch wheel before installing this package.
The CPU build remains fully functional.

## Reproduce the controlled study

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_pilot.ps1
```

This downloads both datasets, runs the bounded interpolation experiments and
capacity diagnostics, and regenerates figures. Exact commands are kept in the
script rather than copied manually into a notebook.

## Run one custom experiment

```powershell
python -m tree_nn.cli train `
  --dataset cifar10 `
  --cifar-source huggingface `
  --train-size 256 `
  --test-size 1000 `
  --trunk-width 16 `
  --root-hidden 64 `
  --root-target-accuracy 0.85 `
  --root-epochs 100 `
  --max-nodes 20 `
  --node-hidden 64 `
  --node-epochs 30 `
  --target-accuracy 0.999 `
  --run-name main
```

## Run a repeated-seed capacity sweep

```powershell
python -m tree_nn.cli sweep `
  --dataset cifar10 `
  --cifar-source huggingface `
  --train-size 64 `
  --test-size 256 `
  --cache-images `
  --batch-size 64 `
  --label-noise 0.10 `
  --widths 1 2 4 8 16 32 64 `
  --seeds 42 43 44 `
  --root-target-accuracy 0.95 `
  --root-epochs 80 `
  --eval-every 5 `
  --max-nodes 10 `
  --node-epochs 50 `
  --node-lr 0.005 `
  --sweep-name interpolation_sweep
```

Noise is applied only to training labels. Run a clean sweep separately if the
effect of noise itself is under discussion.

## Full-dataset GPU experiment

`scripts/run_all.ps1` contains the full configurations. It trains both main
models and independent capacity sweeps, then regenerates the report. These
runs are intentionally not disguised as cheap: full repeated-seed sweeps
require substantial compute.

## Output contract

Every main run writes:

- `config.json` — exact hyperparameters and subset sizes;
- `metrics.json` and `metrics.csv` — every reported root/child stage;
- `summary.json` — class names, device, pruning indices, parameter counts;
- `model.pt` — reconstructable architecture and weights;
- `learning_curves.png` — progress toward interpolation;
- `tree.png` — confusion purpose and pruning status of children;
- `receptive_fields.png` — root/shallow/middle/deep ERFs.

Every sweep writes raw JSON/CSV and a mean ± standard-deviation capacity plot.
No default metric is fabricated when a run is absent.

## Build the formal report

The report is a conventional monochrome LaTeX paper:

```powershell
Push-Location report
tectonic main.tex --outdir .
Copy-Item main.pdf corrective_neural_tree_report.pdf -Force
Pop-Location
```

The paper includes only project-relevant academic content: formulation,
implementation decisions, protocol, measured results, interpretation,
conclusions, limitations, and future work. Detailed operational documentation
remains here rather than padding the report.

## Verification

The tests check sign constraints, zero-sum corrections, checkpoint round trips,
dominant-confusion selection, child masking, missing-result behavior, and the
multi-seed guard against false double-descent claims.

See [`docs/reproducibility.md`](docs/reproducibility.md) for the full audit
checklist and [`docs/results.md`](docs/results.md) for a human-readable index of
the committed measurements.
